# tests —— 项目的自查脚本

这里放的是**能反复跑的验证脚本**。它们不参与网站运行，只用来回答一个问题：
**"我改完代码，原来的东西还好好使吗？"**

每条命令跑完看两样东西：屏幕上写的"结论"，和退出码。

- **退出码 0** = 全过
- **退出码 1** = 有没过的，屏幕上会列出是哪一条

（退出码怎么看到手：紧跟着命令输入 `echo $?`，Windows 的 cmd 里是 `echo %errorlevel%`。）

---

## 四条命令

在**仓库根目录**（`G:\vibecoding`）下跑：

```bash
node tests/inject-test.js          # 后端错误提示，26 条
node tests/network-test.js         # 断网/超时/接口挂，6 条
node tests/log-test.js             # 请求日志，6 条
node tests/scan-positive-check.js  # 密钥扫描器的有效性对照，6 种
```

根目录还有一个安全工具（不属于测试，所以没放进这个目录）：

```bash
node secret-scan.js                # 查仓库里有没有真实密钥被写进文件
```

---

## 各自验的是什么

### 1. `inject-test.js` —— 后端报错是不是人话（26 条）

把后端（云函数）的两类错误**真跑一遍**，看它到底返回什么：

- **用户输入错**（21 条）：参数填错、填空、填了负数、重复收藏、改/删一条不存在的记录……
- **服务端错**（5 条）：模拟"数据库表被改坏了"，看是不是还好好说话

服务端错**不是真去改线上数据库**——是往共享模块里塞一个假数据库对象，让它返回和真实故障一样的错误。走的是同一段代码、同一个错误处理分支，效果和真改坏表名一样，但不用动线上。

每条都自动检查三件事：

1. 返回的是约定好的错误码（比如 `BAD_PARAM`、`NOT_FOUND`）
2. 提示里有**中文**（用户看得懂）
3. 提示里**没有**英文原始报错（`relation does not exist`、`duplicate key` 这类一串英文，绝不甩给用户看）

### 2. `network-test.js` —— 断网时用户看到什么（6 条）

第三类错误发生在"网络这一层"，后端代码根本没执行到，所以不能用上面的办法测。
这里的做法是：把浏览器发请求的动作（`fetch`）换成一个我们能控制的假实现，模拟断网、超时、接口挂掉。

顺带验一条重要规则：

- **网络问题 → 自动重试一次**（断网、超时都是发 2 次请求）
- **业务问题 → 不重试**（"已经收藏过了"只发 1 次，重试会造成重复操作）

### 3. `log-test.js` —— 请求日志（6 条）

每次请求会在云函数日志里留下一行，长这样：

```
[2026-10-13T15:24:20.412Z] PATCH /api/favorites/11 ok 0ms
```

时间、方法、路径、结果、耗时。成功记 `ok`，失败记错误码。

验四件事，其中第 4 条是安全边界：

1. 五个要素都在
2. 成功/失败一眼能分清
3. **预热调用不写日志**（它每分钟来一次，写了会把有用的信息淹掉）
4. **用户输入不进日志** —— 查询词、备注正文都不许出现在日志里。
   脚本里故意塞了一个私密查询词和一段备注正文，断言日志中不得出现。

日志会留存很久，把用户敲的内容写进去既没必要也不安全。

### 4. `scan-positive-check.js` —— 证明"0 命中"是真的

这条最容易被人忽略，但**最重要**。

一个永远报"没问题"的检查，等于没检查。所以这个脚本在一个临时目录里另起一个 git 仓库
（**绝不碰主仓库**），提交一份装着六种假密钥的文件，再用和 `secret-scan.js` 完全相同的
规则去查，看它抓不抓得到。六种都抓到 = 规则有效，那么主仓库报 0 命中才是"真没有"，
而不是"查不出"。跑完临时仓库自动删除。

---

## 什么时候该跑

- 改了后端（云函数）代码之后 → 跑 1、3
- 改了前端请求相关代码（`api.js`）→ 跑 2
- 改了 `secret-scan.js` 的规则 → **必须**跑 4
- 拿不准就四条全跑，一共几秒钟

---

## 两个说明

**这些脚本不需要联网、不需要数据库。** 后端测试注入了假数据库对象，前端测试替换了发请求的动作，
所以换台电脑 clone 下来也能直接跑。

**`scan-positive-check.js` 里故意写着假密钥**，那是给扫描器当靶子用的样本，不是泄漏。
`secret-scan.js` 已经把它登记为例外（和跳过自身同一个道理），所以主仓库扫描不会被它干扰。
