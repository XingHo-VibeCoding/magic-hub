4. 收藏记忆键从「区块+序号」改为「区块+标题」：筛选会改变卡片顺序，序号键会让收藏错位。

## 2026-09-27｜Day 12 追加：顶栏搜索入口 + 全屏搜索层（紫光同款）

**触发**：用户问「紫光把搜索放在哪」→ 查存档证据（home.html 364–390 行、top.css 127–131 行）：顶栏右侧只有放大镜图标（`.searchBox .searchBtn`，21px），点击展开**全屏搜索层**（`searchformMain`，fixed 铺满 + `search_mask` 遮罩 + 大输入框 + 关闭按钮）。用户拍板对齐此互动（选项 B）。

**按「修改前检查」执行的决策**：
1. 入口用 `<button>`（键盘可按），不用参考站的 `<a href="#">` 假链接——SKILL.md「不做假按钮」。
2. 图标配色复用导航链接的同一规则：透明顶栏白色 → `.solid` 深灰 → 悬停主紫，不新造色值。
3. 搜索层 z-index 500 压过顶栏 100（同 toast 的层级思路）；深色遮罩上的无结果框重写底色文字色（state-box 原是浅底样式）。
4. 结果点击**复用现成筛选逻辑**（给区块筛选框填词 + dispatch input 事件），不另写一套筛选——两处行为永远一致，符合「同类交互一处实现」。
5. 无障碍：`role="dialog"` + `aria-modal`、打开即聚焦输入框、Esc / 关闭按钮 / 点遮罩三种退出、关闭后焦点还给触发按钮、背景滚动锁定。

**验证结果**：新增专项测试 17/17（开关/结果/跳转填词/无结果/Esc/遮罩/重开清空/分区页功能搜索/零报错）；回归 Day 12 筛选 18/18、Day 11 冒烟 15/15、压力 15/15、Day 8 四状态 8/8，全部全绿。

**测试侧修的假失败**：`.open` 类在 requestAnimationFrame 下一帧才挂上，测试同步断言会闪失败 → 断言前等一拍（setTimeout 30ms）。页面代码无改动。

## 2026-09-28｜Day 13 板块②：资料库页与多级切换

**触发**：Day 13 主任务「实现 3 个页面或独立视图」。用户拍板切换方式 **B（顶层多页 + 页内视图）**。

**按「修改前检查」执行的决策**：
1. 新增的资料库页复用既有组件族：卡片直接调 `renderCards`（收藏/复制交互免费获得）、搜索框复用 `.filter-input`、返回按钮复用 `.btn-retry` 家族、提示复用 `.state-box`。
2. 面包屑末项同时挂 `aria-current="page"`；分类标签选中态用 `aria-pressed`（不是 :checked，因为不是表单控件）——可访问性是每次必查项。
3. 详情的正文区**不编假内容**：用虚线占位框说清"以后这里有什么"，符合项目"不假装"原则。
4. 分区页原「资料库」灰态卡改成 `feature-card-link`（主紫徽标 + 悬停浮起 + 「进入资料库 →」），与仍是灰态的其余卡**视觉上划清可点/不可点**——SKILL.md「不可点的绝不做成按钮样子」的反向应用：可点的必须看着能点。
5. 同一文件多处编辑全部串行（app.js 6 处、styles.css 1 块、5 个 HTML）。

**发现并修复的问题**：
1. 首页筛选后卡片会丢掉「查看详情」入口（筛选路径与成功态路径各调一次 renderCards，只改了一处）→ 两处都传 detailPath，测试加断言「筛选后入口仍在」。
2. 详情链接曾用"筛选结果内的序号"——筛选后序号会指错资料 → 改用「在完整数据里的位置」（`fullList.indexOf(item)`）。
3. 回归测试又出一次结构性假失败：卡片加第三个按钮后 `test-day11-smoke.js` 的数量断言仍写 32（实为 48）→ 已同步，并把「结构类断言（按钮数/卡片数）也要同步」写进 SKILL.md 修改前检查第 4 条。

**验证结果**：Day 13 专项 28/28（入口/列表/详情/深链/后退/无效编号/标签+关键词/搜索层联动/四页零报错）；回归 Day 8 8/8、Day 11 15/15 + 15/15、Day 12 18/18 + 17/17，全部全绿。

## 2026-09-28｜Day 13 板块③：资料库列表补齐四种状态

**触发**：Day 13 完成标准「空、加载、错误、正常四种状态都能看到」。资料库列表此前只有成功态。

**按「修改前检查」执行的决策**：
1. **不新造组件**：先读 `styles.css` 状态区确认 `.skeleton-card` / `.state-box` / `.btn-retry` 都在且可复用 → **本轮 CSS 零改动**；加载态直接调首页的 `renderSkeleton`。
2. **不发明第二套机制**：状态演示继续用首页已有的 `?state=loading/empty/error` 网址参数，两个资料库页共用同一入口函数 `start()`。
3. **空态分两种，文案不许混**：①库里真没数据（「这个资料库还没有内容」）②筛选没命中（「没有找到相关内容」+ 查看全部）。两种都不白屏、都给出下一步——SKILL.md「失败必须给下一步」。
4. **改共用函数先想副作用**：`renderError` 加了可选的 `onRetry`，资料库页传自己的重试（回列表），首页不传走原逻辑——避免"资料库重试后跳到首页那套渲染"。签名改动后必须跑首页四状态回归，已跑。
5. 所有新文案已过研发词表扫描（新增一条自动断言：四态渲染出的文字里不许出现词表词）。

**发现并修复的问题**：
1. **资料库页筛选无结果时是一片空白**（Day 13 板块②遗留：`renderList` 直接 `renderCards(matched())`，空数组就渲染出空网格，没有提示也没有下一步）→ 补无结果提示 + 「查看全部」，并把关键词、分类标签、aria 选中态一起复位。这条是本次四状态补齐顺带抓出来的真 bug。

**验证结果**：Day 13 状态专项 24/24（四态 + 错误态重试恢复 + 重试后筛选可用 + 无结果与查看全部 + 演示态下筛选不抢戏 + 两库一致 + 词表干净 + 详情视图回归 + 零报错）；回归 101 项全绿。

**本轮无回归假失败**——说明「结构类断言同步」已生效：改状态渲染不影响按钮数/卡片数断言。

## 2026-09-28｜Day 13 板块④：登录 / 注册界面（会员中心）

**触发**：Day 13 用户追加要求「做用户注册和登录界面，去紫光同创参考」；用户拍板「只做界面 + 校验，不做假登录」。

**先取证再动笔**（不凭印象模仿）：
- 存档 `home.html`：顶栏「会员中心」是**跳转到独立页** `/member/index/`，不是弹窗；顶栏右侧还带一个 21px 放大镜（与我们 Day 12 做的入口一致）。
- 抓 `pangomicro.com/member/index/`：未登录时该页**直接就是登录表单**——「用户登录」+ 邮箱 / 密码 / 图片验证码 + 「登 录」按钮，底部「还没账号? 注册」「忘记密码」。
- 抓 `/register/`：`注册账号` + 单列表单 + 密码规则说明 + 协议勾选（「创建账号即表示同意《隐私政策》」）+ 底部「已有账号？ 登录」；字段是企业版（公司/职位/省市），**结构照抄、字段改学生版**（院校 / 身份 / 参赛方向）。

**按「修改前检查」执行的决策**：
1. 表单字段**复用** `.filter-input` / `.filter-select` 的颜色、边框与聚焦光晕（主紫描边 + 浅紫光晕），提交按钮直接 `class="btn-retry btn-auth"` 复用胶囊按钮——本轮的 CSS 新增只有"布局与状态"，没有新造颜色。
2. 一处**刻意的例外并在注释里说明理由**：满宽表单字段用 `--radius` 卡片圆角而非胶囊 999（满宽胶囊不成形）；这是"同类构件同语言、不同构件按形态取形"，不是随手加样式。
3. 无障碍每次必查：`label for` 与控件 id 一一对应、错误用 `aria-invalid` + 下方红字、结果提示 `role="status"`、`novalidate` 关掉浏览器气泡改用统一错误文案（错误必须写清改法）。
4. **不做假链接**：`《用户协议》` 不挂 `href="#"`（纯文本）；「忘记密码」无页面 → 用 `<button data-soon>` + 提示条说清现状，不用假 `<a>`。
5. 7 个页面顶栏同步（含两个新页）：会员中心由"不可点的 span 占位"升级为真链接，并加 `aria-current="page"` 标出当前页 —— **先有页面再通链接**，避免中途出现死链。
6. 同一文件多处编辑全部串行；5 个页面的同款替换分文件执行。

**发现并修复的问题**：
1. `.field > label` 的加粗（字段名要粗）会连带把协议正文也变粗 → `.check-row` 显式 `font-weight: 400`。
2. Day 10 顶栏测试里两条断言现在**必然过期**（原设计要求"是 span 非 `<a>`、带『即将开放』title"）→ 按新设计改写为"是真链接且指向登录页""已无 span 占位"，并把覆盖页数从 3 页扩到 7 页。这是**设计变更导致的有意更新**，不是掩盖失败。

**验证结果**：新增专项 34/34（空提交全量报错并聚焦首错、邮箱格式、密码强度、两次一致、用户名规则、身份下拉、协议勾选、验证码大小写不敏感与换一张、提交后换码、如实说明不假装、忘记密码走提示、方向标签多选、零报错）；回归 topbar 55/55 + Day 8 8/8 + Day 11 15/15 + 15/15 + Day 12 18/18 + 17/17 + Day 13 28/28 + 24/24，共 214 项全绿；真实 HTTP 请求 `/login.html`、`/register.html` 均 200。
